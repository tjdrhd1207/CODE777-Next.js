## 오늘 한 것

### 1. submit_answer 처리 순서 확정

서버에서 이벤트를 emit하는 순서가 클라이언트 UX에 직결됨:

```
1. checkAnswer()       → 정답/오답 판별
2. scores 업데이트     → 정답인 경우만
3. emit answer_result  → 오버레이 먼저 표시 (반드시 dealNew 이전)
4. dealNew()           → 타일 교체
5. currentTurnIndex++  → 턴 이동
6. questionDeck.pop()  → 새 질문 뽑기
7. evaluate()          → 새 손패 기준 정답 계산
8. emit stands_updated → 새 타일 화면 반영
9. emit turn_changed   → 다음 턴 + 새 질문
```

**타일 교체 범위**
- 정답: 모든 플레이어 + NPC 전부 새 패
- 오답: 제출자 + NPC만 교체

### 3. 패 교체 순차 애니메이션

**타이밍 설계** (`useGameSocket.ts` `answer_result` 핸들러)

```
0ms    → collecting  : 카드들이 각 방향으로 날아감 (오버레이 뒤에서)
400ms  → shuffling   : 셔플 덱 대기 (오버레이 뒤에서)
2500ms → answerResult null : 정답/오답 오버레이 사라짐
         shuffling 오버레이 노출
3300ms → dealing     : stands_updated 적용 + 딜 애니메이션
4000ms → idle
```

**stands_updated 버퍼링 패턴**

서버는 `answer_result`와 `stands_updated`를 연속 emit하지만,
클라이언트는 `stands_updated`를 즉시 반영하면 애니메이션과 겹침.

```ts
// 버퍼에 저장
socket.on('stands_updated', (data) => {
    pendingStandsRef.current = data.visibleStands;
});

// answer_result 타이머(3300ms)에서 꺼내 적용
// 핵심: 반드시 로컬 변수에 캡처 후 setState
const stands = pendingStandsRef.current;
pendingStandsRef.current = null;          // ← 먼저 초기화
if (stands) setGameState(prev => ({ ...prev, visibleStands: stands }));
```

> **주의**: `setGameState(prev => ({ visibleStands: pendingStandsRef.current }))` 처럼 쓰면
> React updater 함수가 비동기 실행될 때 ref가 이미 null이 되어 `visibleStands: null`이 됨.

**CSS 클래스 추가**

| 클래스 | 설명 |
|--------|------|
| `stand-collect-{top/bottom/left/right}` | 각 방향으로 카드 날아가기 (0.4s ease-in) |
| `.shuffle-overlay` | 셔플 덱 오버레이 (fixed, z-index:200) |
| `.shuffle-deck-card` | 팬 형태로 퍼지는 카드 애니메이션 |
| `stand-deal-{top/bottom/left/right}` | 각 방향에서 카드 날아오기 (0.45s ease-out) |

### 4. reconnect grace period (재연결 유예 시간)

```js
// socketId -> reconnect 대기 타이머
const reconnectTimers = new Map();

socket.on('disconnect', () => {
    const info = socketToRoom.get(socket.id);
    if (!info) return;

    const timer = setTimeout(() => {
        reconnectTimers.delete(socket.id);
        leaveRoom(socket, info.roomId, info.userId);
    }, 10000); // 10초 유예
    reconnectTimers.set(socket.id, timer);
});
```

재연결 시 `join_room`에서 같은 `userId + roomId`의 타이머를 취소:

```js
socket.on('join_room', ({ roomId, userId }) => {
    // 기존 disconnect 타이머 탐색 후 취소
    for (const [sid, timer] of reconnectTimers.entries()) {
        const info = socketToRoom.get(sid);
        if (info?.userId === userId && info?.roomId === roomIdStr) {
            clearTimeout(timer);
            reconnectTimers.delete(sid);
            break;
        }
    }
    // ...
});
```

**동작 원리**
- Socket.io는 앱 전환 등 짧은 네트워크 끊김 시 자동 재연결 시도
- 10초 안에 재연결하면 `leaveRoom` 호출 안 됨 → 게임 유지
- 10초 초과하면 정상 퇴장 처리

### 5. 턴 타이머 (60초 자동 진행)

**서버 구조**

```js
const turnTimers = new Map(); // roomId -> setTimeout handle
const TURN_TIMEOUT_MS = 60_000;

function startTurnTimer(roomIdStr, io) {
    clearTurnTimer(roomIdStr);
    turnTimers.set(roomIdStr, setTimeout(() => {
        autoAdvanceTurn(roomIdStr, io); // 60초 후 자동 다음 턴
    }, TURN_TIMEOUT_MS));
}

// 호출 시점: game_started, next_turn, submit_answer
// 취소 시점: next_turn 수신, submit_answer 수신, game_over
```

`turn_changed` 이벤트에 `turnDeadline` (Unix 타임스탬프) 포함:
```js
const turnDeadline = Date.now() + TURN_TIMEOUT_MS;
io.to(roomIdStr).emit('turn_changed', { currentTurn, question, answer, turnDeadline });
```

**클라이언트 카운트다운 계산 방식**

서버에서 매 초 전송하지 않고, `turnDeadline`을 한 번 받아 **로컬에서 계산**:

```ts
// 턴이 바뀔 때마다 deadline 저장
socket.on('turn_changed', (data) => {
    if (data.turnDeadline) turnDeadlineRef.current = data.turnDeadline;
});

// 500ms마다 로컬 계산 (소켓 통신 없음)
useEffect(() => {
    const interval = setInterval(() => {
        const left = Math.max(0, Math.ceil((turnDeadlineRef.current - Date.now()) / 1000));
        setTurnTimeLeft(left);
    }, 500);
    return () => clearInterval(interval);
}, []);
```

> `turnTimeLeft`는 소켓에서 받는 값이 아니라 훅 내부 `setInterval`이 계산하는 로컬 state.
