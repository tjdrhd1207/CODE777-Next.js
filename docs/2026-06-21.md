### 1. 게임 화면 UI 구현 (Step 2)

**게임 보드 레이아웃**
```
        [NPC 받침대]
[플레이어A]  [질문/점수 패널]  [플레이어B]
        [나 (뒷면)] [버튼]
```

- `TileCard` — 앞면(SVG 이미지) 또는 뒷면(`?`) 렌더링
- `PlayerStand` — 이름 뱃지 + 타일 3장 + 현재 턴 표시(금색 링)
- 본인 타일은 항상 뒷면 — 서버가 처음부터 본인 타일을 안 보내기 때문

**버튼 동작**
- "다음 턴" — 현재 턴인 플레이어만 활성화, `next_turn` emit
- "정답 도전" — 모달 열림, 숫자 3개 선택 후 제출

### 2. 컴포넌트/훅 분리 리팩토링

파일 한 곳에 모든 로직이 몰리는 문제를 분리:

| 파일 | 역할 |
|------|------|
| `app/hooks/useGameSocket.ts` | 소켓 연결 + 모든 이벤트 + 관련 상태 |
| `app/components/game/TileCard.tsx` | 타일 카드 렌더링 (앞/뒷면) |
| `app/components/game/PlayerStand.tsx` | 받침대 (이름 + 타일 3장) |
| `app/game/[id]/page.tsx` | 로비/게임 화면 렌더링만 담당 |

**핵심 이유**: `page.tsx`가 소켓 로직 + 타입 + 컴포넌트 + UI를 전부 담으면 수정 범위를 파악하기 어려움. 역할 분리로 유지보수성 향상.

### 3. next_turn / submit_answer 서버 이벤트

**next_turn 흐름**
```js
// 현재 턴 플레이어만 가능 (서버 검증)
gs.currentTurnIndex = (gs.currentTurnIndex + 1) % gs.playerOrder.length;
const question = gs.questionDeck.pop();
const answer = evaluate(question.seq, players, nextTurnIndex);
io.to(roomIdStr).emit('turn_changed', { currentTurn, question, answer });
```

**submit_answer 흐름**
```
정답 → 점수 +1, 제출자 타일 3장 교체
오답 → 제출자 타일 3장 교체 + NPC 타일 3장 교체
→ 항상 stands_updated 전송 (모든 플레이어 화면 갱신)
```

**checkAnswer 동작 방식**
```js
// 숫자만 비교, 색상 무관, 순서 무관
[1, 5, 7] 제출 → 정렬
실제 손패 [{value:7}, {value:1}, {value:5}] → 값만 추출 후 정렬
→ [1,5,7] === [1,5,7] → 정답
```

### 5. 버그 수정

**방 생성 시 NULL 에러**
- 원인: `Rooms.id` 컬럼이 NOT NULL인데 INSERT 쿼리에 누락
- 해결: `id-{타임스탬프}` 형식으로 생성해서 명시적으로 삽입

```ts
// Before: id 컬럼 누락 → NULL 삽입 시도 → 에러
INSERT INTO Rooms (name, capacity, ...)

// After: id 생성 후 명시적 삽입
const id = `id-${Math.floor(Date.now() / 1000)}`;
INSERT INTO Rooms (id, name, capacity, ...)
```
