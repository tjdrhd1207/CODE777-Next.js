### 3. next_turn / submit_answer 서버 이벤트

**next_turn 흐름**
```js
// 현재 턴 플레이어만 가능 (서버 검증)
gs.currentTurnIndex = (gs.currentTurnIndex + 1) % gs.playerOrder.length;
const question = gs.questionDeck.pop();
const answer = evaluate(question.seq, players, nextTurnIndex);
io.to(roomIdStr).emit('turn_changed', { currentTurn, question, answer });
```

**submit_answer 흐름**
```
정답 → 점수 +1, 제출자 타일 3장 교체
오답 → 제출자 타일 3장 교체 + NPC 타일 3장 교체
→ 항상 stands_updated 전송 (모든 플레이어 화면 갱신)
```

**checkAnswer 동작 방식**
```js
// 숫자만 비교, 색상 무관, 순서 무관
[1, 5, 7] 제출 → 정렬
실제 손패 [{value:7}, {value:1}, {value:5}] → 값만 추출 후 정렬
→ [1,5,7] === [1,5,7] → 정답
```

### 5. 버그 수정

**방 생성 시 NULL 에러**
- 원인: `Rooms.id` 컬럼이 NOT NULL인데 INSERT 쿼리에 누락
- 해결: `id-{타임스탬프}` 형식으로 생성해서 명시적으로 삽입

```ts
// Before: id 컬럼 누락 → NULL 삽입 시도 → 에러
INSERT INTO Rooms (name, capacity, ...)

// After: id 생성 후 명시적 삽입
const id = `id-${Math.floor(Date.now() / 1000)}`;
INSERT INTO Rooms (id, name, capacity, ...)
```

### 6. submit_answer 처리 순서 확정

서버에서 이벤트를 emit하는 순서가 UX에 직접 영향을 줌:

```
1. checkAnswer()          → 정답/오답 판별
2. emit answer_result     → 오버레이 먼저 표시 (이게 먼저여야 함)
3. dealNew()              → 타일 교체 (오버레이 뒤에서 진행)
4. currentTurnIndex++     → 턴 이동
5. questionDeck.pop()     → 새 질문 뽑기
6. evaluate()             → 새 손패 기준 정답 계산
7. emit stands_updated    → 새 타일 화면 반영
8. emit turn_changed      → 다음 턴 + 새 질문
```

**타일 교체 기준**
- 정답: 모든 플레이어 + NPC 전부 새 패 (`playerOrder.forEach + dealNew('npc')`)
- 오답: 제출자 + NPC만 교체

### 8. 패 교체 순차 애니메이션

**타이밍 설계** (`useGameSocket.ts` 내 `answer_result` 핸들러)

```
0ms    : answer_result 수신 → 정답/오답 오버레이 + collecting 시작 (오버레이 뒤에서)
400ms  : shuffling 페이즈 전환 (오버레이 뒤에서 대기)
2500ms : 오버레이 사라짐 → 셔플 오버레이 노출
3300ms : stands_updated 적용 + dealing 페이즈 → 딜 애니메이션
4000ms : idle
```

**핵심: `stands_updated` 버퍼링**
서버는 `answer_result`와 `stands_updated`를 연속으로 emit하지만,
클라이언트는 `stands_updated`를 즉시 적용하면 안 됨.

```ts
// 버퍼에 저장
socket.on('stands_updated', (data) => {
    pendingStandsRef.current = data.visibleStands;
});

// answer_result 타이머(3300ms)에서 꺼내 적용
const stands = pendingStandsRef.current;
pendingStandsRef.current = null;          // null 초기화 먼저
if (stands) setGameState(prev => ...);    // 캡처된 값으로 setState
```

> **주의**: `setGameState(prev => { visibleStands: pendingStandsRef.current })` 처럼 쓰면
> React가 updater를 비동기 실행할 때 이미 `null`이 돼 있어 `visibleStands: null`이 됨.
> 반드시 로컬 변수에 캡처 후 사용해야 함.

**CSS 애니메이션 클래스**

| 클래스 | 역할 |
|--------|------|
| `stand-collect-{dir}` | 각 방향으로 카드 날아가기 (0.4s ease-in) |
| `.shuffle-overlay` | 셔플 덱 오버레이 (fixed, z-index:200) |
| `.shuffle-deck-card` | 팬 형태로 퍼지는 카드 (deck-card-spread 무한) |
| `stand-deal-{dir}` | 각 방향에서 카드 날아오기 (0.45s ease-out) |

### 11. 방 목록 실시간 인원수 수정

**문제**: `rooms_changed` → `fetchRooms()` 하면 DB에서 방 정보를 가져오는데,
DB에는 실시간 인원수 필드가 없어 `players: undefined`로 덮어씌워짐.

**해결**: fetch 완료 후 `get_room_list` 재요청으로 소켓에서 인원수 재수신

```ts
socket.on('rooms_changed', () => {
    fetchRooms().then(() => {
        socket.emit('get_room_list'); // DB fetch 후 인원수 재요청
    });
});
```
